# Pi24 opt-in fixed-version serving

Product candidate for WorkOrder [24](https://github.com/pym96/pi-agent-platform/issues/24). This entry does not authorize GPU use; the Master freezes the complete source/runtime/model/device/entry/watch/plan identities and a fresh nonce/deadline before each lifecycle. Default Transformers and Go/Pi source are unchanged. This is a functional integration experiment, with one engine sequence and original platform workers, not a throughput tuning result.

`launch.py --go <frozen-json> --go-sha256 <digest>` requires the exact role root and clean source SHA. It validates fixed existing assets, obtains two GPU0 empty snapshots at least ten seconds apart, consumes the nonce once, starts an independent watchdog, and runs only the prescribed functional matrix. All input assets are read-only and images are cached. The original compatibility native hard deadline and native535 driver selector are reused unchanged. G2.3 keeps one pre-created internal bridge and publishes no host ports. CPU preparation records its exact network ID and labels; the GO binds that ID. The foreground client accepts only a hashed endpoint map and revalidates exact container labels, network identity/Internal state, container membership/IP correspondence and fixed internal ports before sending. The compose external-network reference means an already created owned bridge, whose actual Internal property must be true; it does not permit Internet egress. Engine6CPU plus Pi2/PG1/Go1 leaves two CPU for the single-thread foreground client/watch and serial Docker helpers; containers total35GiB, with host helper memory measured separately within36GiB. The sole original Transformers fallback retains its original intra-op6/OMP6 configuration under its6CPU cap; other vLLM OMP remains at most4. GPU exposure, failed startups and partial requests count toward the WorkOrder budget.

`watch.py` acts on exact full CIDs with project/workorder24/source/nonce labels. Failed inventory stays unknown, and known owned objects are still reconciled independently. It stops on the absolute deadline or foreign GPU0 work, and never stops a foreign object. PostgreSQL/Pi diagnostic data remain retained. `owned.py` provides the common exact-ID ownership/stop/remove interface. No global Docker settings, driver paths or packages are changed.

`client.py` records payloads before sends and partial SSE bytes during reads. The fixed plan separates successful direct requests, direct cancellation, deadline, durable platform SSE replay, API restart uncertainty/new-session recovery, and explicit original Transformers fallback. Platform tasks keep their actual128-token requested budget; direct budgets are16/64/128. Native token records and model-monotonic transitions are retained independently of HTTP observations. Direct cancellation has unknown final usage unless the engine supplied terminal token information; SSE subscription requests are not generations. Health/SQL reads are distinct from completion POSTs.

`endpoints.py` creates a fresh labelled internal network during CPU preparation, resolves exact live endpoints, verifies frozen maps, and removes only its exact empty network after container cleanup. It rejects a private address whose network membership, source/nonce or published-port state differs. No arbitrary model/API URL is accepted by the client CLI.

Its taskset/RSS/absolute-deadline and exact-cleanup behavior remains separate and unchanged. No current phase or CPU result authorizes a model start.
