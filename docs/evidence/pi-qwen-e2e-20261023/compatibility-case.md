# #12 compatibility and completion case (candidate)

Human asked to connect the Pi platform to local Qwen and learn inference infrastructure through measured iterations. Master froze E2E1.0; this Working Agent implemented and tested this candidate. Upstream supplies the Pi SDK and Transformers runtime. This record does not attribute Agent implementation to Human or promote a resume fact.

Initial hypothesis: a URL change plus the existing final Pi result might suffice. Regulator's early static challenge identified normalized usage and weak completion semantics. The Builder then ran actual Pi1.3.0 against a controlled upstream stream: the upstream omitted usage, yet Pi emitted result with zero counters. [Original wire](initial-sdk-wire-red.json) preserves that failure. HTTP200 and a final SDK message could therefore misclassify a broken upstream exchange.

The candidate adds an explicit Qwen-only HTTP bridge at the provider seam. It forwards nonempty content immediately, validates the original upstream finish/usage/DONE and EOF, and withholds terminal markers on failure. The existing strict #9 schema stays strict; the bridge maps SDK text arrays, max_completion_tokens, include_usage=true and store=false explicitly. It rejects unknown fields. Go now validates result data and waits for complete NDJSON EOF before writing completed. PostgreSQL remains authoritative for durable completion.

A positive test then found another mismatch: SDK streamSimple reserves4096 context tokens and reduced a1024-context model's output budget to1. The fixture returned2 tokens and the bridge rejected it correctly. The Builder considered contextWindow=0 but withdrew that option after finding the public Agent.streamFunction / ModelRuntime.stream interfaces. Master selected the narrower public API route: preserve the physical context declaration1024, set explicit maxTokens128, and retain actual-tokenizer admission in #9. No upstream package was edited; no5120-token model capability was claimed.

CPU checks cover raw errors, invalid/missing usage, terminal/DONE truncation, empty text and late frames, plus actual SDK → strict HTTP fixture → dedicated PostgreSQL → client SSE. Same-session continuation and replay after subscriber disconnection retain the original durable ownership semantics. Removing the bridge's DONE requirement made the same required CPU entry fail; restoring its exact bytes returned it to green. Early harness failures (no-test Go package classification, child cwd and a fixed-port collision between overlapping local checks) remain in the original state directory. Ephemeral ports and explicit child cwd fixed those harness errors.

Limits: CPU fixture times are synthetic diagnostics. The candidate has not established a throughput/P95 target, batching gain, GPU preemption, multi-host availability or public-service security. Real-model Stage B needs a fresh identity/deadline binding, raw receipts and independent exact-SHA review.
