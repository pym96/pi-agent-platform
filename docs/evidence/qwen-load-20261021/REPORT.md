## 口径

每轮45秒半开发起/完成窗口[0,45)，最多60秒drain，单请求timeout60秒，105秒后事件不计。窗口req/s=在窗口内完整成功结束的请求数/45；窗口输出tokens/s只累计这些完整完成请求的实际output usage。另保留整个发起cohort的成功/失败/partial/timeout/未决，以及总时长和cohort吞吐。HTTP200、角色/空delta、缺DONE或终态、错误usage均不算完整成功。

语料32条，每条实际prompt242tokens，输出上限128；输出按后端生成token ID数量计usage。采样采用后端硬编码do_sample=False，non-thinking和128上限也为后端固定设置。请求中的seed20261021与temperature0属于客户端元数据，后端没有应用RNG seed或读取temperature；greedy不进行随机采样，未启用确定性算子模式。配置和语料在正式运行前锁定，冷启动与10请求热身独立保存，不混入正式曲线。

TTFT对所有存在有效首段非空内容的发送请求统计，包括后来失败者；E2E只对完整成功请求统计。下表列出各自n/缺失和TTFT成功/失败分层。因此closed16-r1的TTFT P50（全28份首内容）可高于E2E P50（24份成功）；每个成功请求自身仍遵循first≤done。两个不同cohort的分位数不要求相同大小关系。P50/P95/P99均为nearest-rank ceil(p*n)，小样本尾部常等于最大值，不能视为稳定SLA。

开环从k=0按k/r计划发送，保留target、实际sent/45与窗口完成率。Rb=12/45，倍率1/2、1、3/2，精确half-up至0.001且下限0.01，锁定0.133/0.267/0.400 req/s。有限窗口内0.267目标会计划13次，实际发送率13/45=0.288889；它来自半开窗口与从0发送的定义，不自动代表发生器故障。64在途上限与drop另记。

## 观察与边界

闭环C1的窗口吞吐0.2000–0.2222req/s、TTFT P50约0.043秒；C32窗口吞吐0.2000req/s，两个rep分别失败20/41、23/41。首内容等待与队列增加同时出现，代码/health均显示最多一个活动generate。队列与59秒请求生命周期上限解释了本配置的失败路径；吞吐的点间差异还受窗口边界、GPU状态和共享主机影响，未测硬件峰值，也没有batching前后收益对照。

开环0.133→0.400req/s期间，窗口完成率0.1333→0.2000req/s；0.267与0.400两点的窗口tokens/s均25.6，而E2E/TTFT随负载提高。完整cohort都完成不意味着窗口内无排队，表中总时长与drain保留了尾部。

模型容器6CPU/28GiB，发生器2CPU/4GiB，allocator目标0.75；Docker inspect和资源原件留存。GPU3专属UUID两次间隔10秒空闲检查通过后才启动，期间无同卡外来计算；GPU2背景任务未停止。实际加载的libcuda.so.535.309.01来自宿主驱动，不通过GeForce cuda-compat绕过。新盘用量远低于60GiB，既有公开模型缓存只读。

1Hz辅助health/progress记录从08:34:40Z左右开始，第一轮closed1-r1结束边界缺失；后续每轮progress首次更新时记录active_generation=0、queued_waiters=0，完整JSONL保留，不能将采样证据扩展为任意时刻无积压。GPU/model/generator08:56:23Z停止，08:57:06Z GPU3为6MiB/util0，无owned运行容器；CPU后分析/绘图随后独立运行并结束。立即停止时util97%是刚结束的利用率采样，不是仍有计算进程，已保留后续零占用观测。

上游Qwen提供权重和模型实现；Human提出目标/提供资源，Builder准备环境、实现测量与执行，独立Regulator在准备期发现时间顺序反例，Master编排和限定修复。Builder另发现usage边界反例，在GPU停止后按授权修复并逐条证明实际统计不变。当前仍待完整独立Verdict；不自动晋升现实简历事实或Human独立实现。
