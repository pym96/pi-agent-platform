# 学习与实验建议：先补解释证据，再决定部署

2026-10-21；Pi #5 研究建议。本页所有练习与实验均为拟议工作，本轮未执行，不因落盘而获得 server/GPU/集群/产品修改授权。本人掌握程度未知。源码与机制出处见[来源清单](来源清单.md)，岗位定位仅更新现有职业路线的唯一 fit map。

## 优先级 1：用已有 Pi Evidence 贯通对象与状态

**对应任务与缺口：** 平台可靠性/Agent 开发均需解释任务在失败中发生了什么。项目已有 accepted 材料，但 Human 是否能独立解释/修改尚未验证；不需要先新增服务。

**最小动作：** 建议 Human 用 45–60 分钟，只读 P01/P03/P04，手画一次 Submit→Claim→Pi→Append→Finish→SSE 的时序；标注 PG、Pi 文件和内存 tail 的权威范围，再解释“模型已收到请求但终态未落库”的窗口。Agent 可以反馈，不能替本人作答。

**可观察结果：** 一页对象/状态图和口述，能指出幂等键防重提交、single-owner lock 限单控制实例、两个 worker 不等于万级执行；对 HTTP 断连、API 重启、Pi 结果不明分别说出当前行为与来源。未读源码的推断显式标未知。

**接受建议/会改变决定的结果：** 能用源码定位每条解释，并在给出反例时区分“任务已接纳、可能已执行、结果已提交”；若能完成，才把该机制作为本人可讲解的面试素材候选，不自动获披露批准。

**成本、停止/转向：** 无安装/费用，最多一小时；若 channel 生命周期或事务概念仍断层，先用两个流程交棒和“记录≠外部效果”补连接，暂缓分布式部署。不要为回答问题重跑原 C10K。

**条件性叙述收益：** 可形成 Human 本人判断与 Agent 原实现分开的讲述，不能写“本人独立完成全部平台”。

## 优先级 2：读现有 hey/Vegeta 原件，重新提出正确问题

**对应任务与缺口：** 平台和推理服务都需要容量判断；已有 P02 的 HTTP 矩阵与 SSE 测量，但没有真实模型吞吐。

**最小动作：** 建议 30–45 分钟，各选一轮 hey 和 Vegeta，在报告/已有 summary 中找控制量、实际发送量、完成量、测量窗口、分位数定义和发生器资源；不新增压测。画“固定 worker 的闭环”和“固定目标速率输入”的两条时间线。

**可观察结果：** 能解释为什么 `-c=100` 不是 100 QPS，`500/s` 不是 500 模型/s；能保留 120s、1,000 重连和 21 写失败，并指出 history toggle 不能证明 SSE cache 加速 history。

**接受建议/决策变化：** 正确区分单位与测量对象后，保留现有 Evidence，不为简历再造一个好看的吞吐数。若来源缺少要回答的量，明确未知；仅在新具体岗位要求改变问题时设计新实验。

**成本、停止/转向：** 仅已有文件，最多 45 分钟；原始数据不可用就以报告边界为止，不把 Builder 报告冒充新的独立复算。

**条件性叙述收益：** 展示负载设计、失败口径与因果判断；不能声称 GPU 模型服务容量。

## 优先级 3：容器的可见性、资源和数据寿命

**对应任务与缺口：** Human 希望补容器化，Pi 已有 Compose/inspect/stop Evidence；当前缺本人操作与解释证据。

**最小动作：** 先 45 分钟只读 P04 与原 inspect/stop 回执，对每个容器标“可见文件/网络、CPU/内存、持久卷、停止后剩什么”。不要先重装 Docker。若本人解释完成，后续 WorkOrder 可允许在隔离教学栈验证容器删除后临时文件消失/卷文件保留、资源限制可观测，并确认清理；不能使用现有业务卷。

**可观察结果：** 第一阶段是一张资源/信任边界图；未来实验需保留实际 inspect、文件前后与清理回执，不能只截图容器 running。

**接受建议/决策变化：** 能说明 namespace 与 cgroup 的区别、volume 不等于备份、socket/特权挂载影响权限后，才决定独立实践是否仍有必要。未满足前，不写“熟悉 Docker/K8s”。

**成本、停止/转向：** 当前阅读低成本；拟议本地实验约一小时且需另定运行范围。需要改共享 daemon、特权挂载或破坏已有卷就停止并缩小。

**条件性叙述收益：** 仅在本人完成并留痕后，可支持受控容器部署/资源排障能力描述，不升级为生产多租户隔离。

## 优先级 4：最小 K8s 教学实验，先区分重启与业务恢复

**对应任务与缺口：** 容器编排方向仍是 Human 的目标；本项目无 K8s Evidence，上海实习 JD 适配待核。

**最小动作：** 先读 S10/S11/S18、画 Deployment→Pod→Container 与 scheduler/kubelet/controller 分工；若后续授权，使用独立本地教学集群和无模型的单副本样例，设置 requests/limits，观察删除 Pod 后新 UID、一个不可满足资源请求导致 Pending，以及明确清理。不要迁移 PG/Pi 或试多副本。

**可观察结果：** YAML、对象 UID/状态/events、调度原因与清理结果；能够解释“控制器补一个 Pod”为什么不能保证原任务 exactly-once。

**接受建议/决策变化：** 本人可预测再解释实际结果才算该练习通过；具体目标岗位确认需要 K8s 时再投资服务迁移。失败若来自资源/环境，就保留为未完成，不绕过共享环境权限。

**成本、停止/转向：** 未来约 1–2 小时、有环境依赖；集群需下载/新资源、影响其他服务或超限时停止，先提交只读解释。该实验不证明多机 HA。

**条件性叙述收益：** 学习/实践可检验，不等于已有 Kubernetes 运维经历。

## 优先级 5：DeepSeek 机制阅读与硬件可行性裁剪

**对应任务与缺口：** 推理服务稿缺真实 GPU 模型 TTFT/TPOT、tokens/s、显存/长度分布和调度测量。先确认硬件与问题，避免把 open-infra-index 的历史指标当可复现目标。

**最小动作：** 建议两段各 45 分钟：先 S02/S03 画 Prefill/Decode、KV cache、batch 与副本负载均衡；再 S04 对照 PG 事件、Pi context 和 3FS 文件层。S05–S07 只选一个具体问题读接口，例如 token dispatch→expert GEMM→combine 或 KV 分页布局，不通读全部代码。

**可观察结果：** 一页“模型/代码版本—设备代际—显存/互连—依赖—可运行性未知项”表，以及对现有 Go 控制面能做/不能做的说明。本轮来源足以证明存在硬件限制，不能证明 server 满足。

**接受建议/决策变化：** 若后续硬件盘点不满足固定版要求，停止 DeepInfer/DeepEP/FlashMLA 运行复现，不默认移植。若目标为服务平台，优先用合适引擎/小模型的有界教学测量而非造完整多卡集群；这仍需另派工和预算。只有实际基准才讨论推理性能。

**成本、停止/转向：** 当前只读约 90 分钟、无 GPU/安装；未来 GPU 时间、模型下载和 RDMA 等成本未知，不在此授权。官方资料开始重复或无法改变近期投入时停止研究，回到本人机制解释。

**条件性叙述收益：** 能作为研究/学习讨论；不能写为 DeepSeek Infra 实现、优化成果或本人已熟练使用这些库。

## 暂缓的工程扩展

不因“分布式系统”关键词就拆微服务、加入 Redis、多控制副本或部署 3FS；现有单实例是否妨碍真实目标尚无证据。若后续明确要研究多控制实例，先提出并审查：谁获得任务、旧执行者还能写什么、Pi 文件放哪里、网络故障如何呈现 unknown，以及外部副作用的幂等/可查询回执。把 PG 锁改成 lease 或加 K8s 不能自动回答这些问题。
